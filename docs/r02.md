## 実装と計測の境界

`src/rosa_repro/adapter.py`はNumPyと標準ライブラリだけを使う。GPU用PythonへR01のOR-Toolsや新しいNumPy/Pandasを入れる必要はない。既存のpolicy/sim環境から`src/`を参照する。

workerは、固定GR00Tコミットのstatelessなpolicyを前提にする。モデルの前処理・正規化・後処理・精度・乱数消費・kernel設定を変更しない。resetは特定robotのエピソード世代だけを進める。一般の状態付きpolicyは対象外。

`MeasuredClient`は、送信から応答のID・出力検査までをクライアントの同じ時計で記録する。workerの時計は混ぜない。`apply()`は実行器の返した実ステップ数を1チャンクのactionとして記録し、推論要求数から行動数を補作しない。失敗・timeoutは要求の分母に残る。実行器が途中で例外を出した場合は、そのrunを失敗として扱い、部分実行のステップ数を推定して記録しない。

今回の共有workerは**直列のbatch 1**で、Ray Serve・動的バッチ・複数要求のテンソル結合は未実装。公式ZeroMQはR02のAPI照合用の足場である。実験計画v3のRay Serveによる実行基盤は後続の結合対象として残し、R03の性能profile取得前に実際の実行経路を固定する。

比較器の合格基準は既定で`atol=0, rtol=0`。差が出たときは数値誤差を記録して原因を調べ、無説明に許容誤差を広げない。同じロード済みモデルの比較なので、別process・別GPU間の再現性を証明するものではない。Torchの専用Generatorなどが将来追加された場合、デフォルトRNGの復元だけでは足りず再レビューが必要。

## 固定コードとの対応

確認した[公式GR00Tコミット](https://github.com/NVIDIA/Isaac-GR00T/tree/944fe70c4fd54e3fcb80a7d7258a328f9c061176)は、前回T01と同じ`944fe70c…`。公開コードを取得し、`run_gr00t_server.py`と`rollout_policy.py`のSHA256が前回run manifestの値に一致することを確認した。

[公式policy](https://github.com/NVIDIA/Isaac-GR00T/blob/944fe70c4fd54e3fcb80a7d7258a328f9c061176/gr00t/policy/gr00t_policy.py)はモデルをBF16へ移し、観測をprocessorに通してからactionをdecodeする。この経路をアダプターは保持する。ただし今回のPodで有効なdtypeや最適化設定を観測できたわけではない。

サーバー起動時にはコミット・追跡対象のgr00tコード差分・前回T01のmodel config/indexハッシュを検査する。全weightのハッシュ検査は未実施で、model revisionの完全な検証済みフラグにはしていない。`runtime_evidence()`はパラメータdtype、compile wrapperの印、attention設定を記録し、CUDA Graphや実kernelが不明なら不明のまま残す。

## Pod再開後の順序

1. 新しいSSH接続先、GPU、ディスク、実行中processを確認する。既存環境が残っているか調べ、必要な場合だけ保存済みruntimeバックアップから復元する。
2. `/workspace/Isaac-GR00T`、checkpoint、Cosmosの固定snapshot alias、policy/sim Pythonを確認する。HF tokenは表示しない。
3. 本実装を別ディレクトリ`/workspace/rosa_reproduction`へ配置する。以前のprototypeとT01結果は維持する。
4. T01の初期状態ID・状態データのハッシュを記録し、公式の観測ラッパーを通ったbatch 1の実観測を保存する。前回のT01ログにはこのデータがなく、保存観測を取得する工程がまだ必要。
5. 保存観測のオフライン照合を10ケースから行う。reset・別robotの応答対応も実モデル接続で確認する。
6. 初期状態をそろえたOfficial対Shared batch 1のT01を各10 episode実行し、数値差・成功・実行ステップ・要求/action対応を確認する。このlive runnerの接続作業も残る。
7. R02合格後にRay Serveとの結合・実際のbatch形成を検証し、R03のprofileを取得する。

以下は手順3・4の完了後に使うコマンド例で、今回実行した記録ではない。出力ディレクトリは新しい名前を指定する。Podの停止や追加GPUのレンタルは含まない。

```bash
cd /workspace/Isaac-GR00T
export HF_HUB_CACHE=/workspace/models/hf-cache
export HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 NO_ALBUMENTATIONS_UPDATE=1
export OMP_NUM_THREADS=8 OPENBLAS_NUM_THREADS=8 MKL_NUM_THREADS=8
/opt/p-ai-policy/bin/python /workspace/rosa_reproduction/scripts/r02_server.py \
  --repo /workspace/Isaac-GR00T \
  --model-path /workspace/models/GR00T-N1.7-LIBERO/libero_object \
  --output /workspace/probes/r02-server-001 --port 5556
```

別のSSH端末で、保存観測のディレクトリを指定する。

```bash
/opt/p-ai-libero/.venv/bin/python /workspace/rosa_reproduction/scripts/r02_compare.py \
  --repo /workspace/Isaac-GR00T \
  --observations /workspace/probes/r02-observations-001 \
  --output /workspace/probes/r02-comparison-001 --port 5556
```

保存観測は各ケースのディレクトリ内に`observation.json`と`arrays.npz`を持つ。`save_observation()`のprovenanceにはtask、初期状態ID・ハッシュ、episode ID、観測時刻/step、ソースrevisionを記録する。現在は実観測のfixtureを同梱していない。

サーバーは`127.0.0.1`へbindする。`r02_reset`・`r02_predict`は`MeasuredClient`に接続するためのendpoint、`r02_compare`は待機中workerでの照合専用。通常の公式`get_action` endpointは比較用に残るが、R02のID検査・計測を迂回するため、共有実験の経路として使わない。
