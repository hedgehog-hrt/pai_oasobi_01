# 同居モデルの期限改善実験（v0.20.7）

単一 GPU の P2〜P4 拡張に、明示指定の `parallel_roles_batch_s1_v1` と `periodic_phases=spread_classes_v1` を追加した。P1 と既存の既定動作は変えない。

## 実行方式

- モデル間は並行呼び出し、各モデルは同時に一つの推論呼び出しを所有する。
- S1 の要求を到着順にまとめ、設定した最大バッチ数または最初の要求の待機期限で実行する。上限は16要求・10 ms。前の推論を待った時間も含め、待機予算を再起算しない。
- 呼び出し元のキャンセル後も実行所有権を保持する。エピソード切替後の出力は破棄し、バッチの出力を元の要求に対応させる。
- VLM は引き続きバッチ1・待機0。GPU の分離やカーネル同時実行は保証しない。
- Safety と Monitor の周期内位相を、それぞれ利用クラス間で等間隔に配置する。P2/P3/P4 各1台では Safety が0/250 ms、Monitor が0/666.666666/1333.333333 ms。同一クラスに複数台ある場合の台ごとの分散は行わない。
- 期限、周期、S1 の要求頻度、行動時間、S2 再利用回数は変更しない。位相は実行計画と監査入力に含め、周期要求の期限は元の予定時刻から計測する。停止・リセット中の欠落は従来どおり評価時間から除外しない。

## 検証と採用

実モデルで使う実バッチサイズは、同じバッチ形状・同じ乱数条件で公式 API と配列比較する。異なるバッチサイズ間の意味品質の同等性は別の検証であり、数値比較だけでは証明しない。`enforce_eager=False` は既存の VLM 設定で明示指定し、runtime fingerprint に結び付ける。

今回の性能目標は S1 200 ms、Safety 500 ms、S2/Monitor 2000 ms。測定前に構成と期間を固定し、失敗試行も残す。短い探索実験での p99 を正式な容量認定、R07 profile 採用、未知入力での期限保証として扱わない。

## MPS の明示設定（v0.20.8）

別プロセスの GPU 処理を並行実行するため、実験専用の NVIDIA MPS を利用できる。`binding.runtime_env.env_vars` に `CUDA_MPS_PIPE_DIRECTORY` と `CUDA_MPS_LOG_DIRECTORY` を対で指定する。任意の環境変数は許可せず、追加指定は `CUDA_MPS_ACTIVE_THREAD_PERCENTAGE` の整数文字列1〜100のみ。これらの設定は実行計画に結び付け、実環境の記録と profile 採用時の runtime signature にも含める。

デーモンの起動だけでは適用の証拠にしない。試験中の MPS 接続クライアントを記録して確認する。推論を drain し、モデルクライアント終了を確認した後、専用 pipe に対して `quit` を送り、自分が起動したサービスのみ終了する。GPU の compute mode は変更しない。MPS 使用時の NVML プロセス表示は MPS server に集約されるため、モデルごとのメモリ使用量として読み替えない。

設計根拠: [NVIDIA MPS 595: 利用条件](https://docs.nvidia.com/deploy/mps/595/when-to-use-mps.html)、[起動・接続確認・終了](https://docs.nvidia.com/deploy/mps/595/quick-start.html)。MPS が有効でも、個別のカーネル重複や期限保証は別途計測が必要。
