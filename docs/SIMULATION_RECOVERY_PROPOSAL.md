# シミュレーション限定の安全退避・再計画実装・検証方針（導入承認済み）

2026-10-31。MuJoCoの衝突確認だけを併用したv0.20.10の確認試験は、測定300秒でP3が157/157停止、P4が85/210停止だった。P3はウォームアップ中に2タスクを完了した後、バスケットへの指先接近で停止し続けた。確認試験全体にはGPU監視のタイムアウトもあり、不合格のまま保存する。

## 承認された範囲

2026-11-01、ユーザーから「安全退避・再計画を追加する」と明示承認を受けた。v0.20.12でモデル出力とは別の退避動作を生成・検証・適用するシミュレーション限定拡張を実装する。S1の拒否は元の記録に残し、退避・S1復帰を独立した証跡で監査する。

2026-11-01補足: 論文§3.2–3.3も停止後の再計画・安全状態への復帰を想定している。復旧の方針自体が論文にないという意味ではない。ここで独自に具体化するのはMuJoCoによる退避候補の生成・検査・実行方法である。[モデル照合](MODEL_ALIGNMENT_20261101.md)でS1が論文のN1.6と異なるN1.7であることを再確認したため、モデル要因の切り分けには、追加制御を入れる前の同条件比較が必要である。

## 提案する処理

1. S1の動作列について、実行区間の衝突確認に加え、予測終端から安全に退避できる候補が残るかを確認する。候補の存在は全状態での安全保証ではない。
2. 退避できない終端へ進む動作は、その手前で拒否する。2mmの距離、2msごとの物理検査、未知・期限超過時の停止を維持する。
3. 最新のVLM判定が許可し、同じMuJoCo検査を通った場合だけ、回数・移動量を制限した退避を適用する。動作・前後状態に結び付いた一回限りの実行証跡を残す。
4. 退避後の実観測でS1を再実行する。P4の計画は更新し、退避前の計画や古いSafety判定を流用しない。安全な候補がない場合は停止を維持する。
5. 元のS1提案の拒否、退避、S1の再開、最終停止を別々に記録する。退避をS1の成功やタスク完了へ付け替えない。繰り返し退避するだけの状態は回復成功としない。

## 実装前に確認したこと

- 保存したP3/P4の停止状態3件で、通常指示と3種類の変更指示を各2乱数条件で実モデルへ入力した。24/24候補は2mm条件で停止した。
- 同じ3状態で上方向の退避候補をシミュレータ上だけで予測した。P4の停止状態と探索P3の停止状態には通過候補があった。確認P3の停止状態では試した4候補がすべて停止した。
- 確認P3について、最後に適用した1チャンク前の状態へ履歴を正確に再生すると、上方向の候補が2mm条件を通過した。これは早期介入の実現可能性を示す限定的な結果であり、制御系への接続・継続動作・タスク完了は未検証である。

## 採用条件

失敗試行を残したまま新しい条件を事前固定する。比較はVLM単独、VLM+衝突確認、VLM+衝突確認+退避の3方式を区別する。P3/P4それぞれ、ウォームアップを除いた測定で停止率・元S1拒否率・実適用数・回復後のS1再開率・タスク完了/打切り・実動作頻度・期限値を報告する。最低100判定、300秒×3回の全試行で基準を確認し、失敗試行を差し替えない。

退避が元のS1拒否を隠す形で停止率を下げた場合は、従来指標の目標達成とは扱わない。GPU監視タイムアウトは別途原因を修正し、欠測を許容へ変更して合格させない。

## v0.20.12の固定条件

上向き制御値は0.1/0.25/0.5、グリッパー値は0.5（現状維持）。1回8cm、1エピソード累計24cm・6回まで。S1が3チャンク適用されるまで連続退避は2回まで。退避前の最新VLMは同じ観測を見た判定に限定し、退避後は新観測のSafetyとP4再計画を必須にする。3回のS1適用が次の退避より先に起きた場合を継続再開と数える。予測終端からの退避候補検査を加えるため、探索も測定300秒＋ウォームアップ60秒で事前固定する。確認300秒×3回は探索の元S1停止率90%以下・100判定以上・両クラスの退避と継続再開・実行/監査/MPS正常を満たしてから開始する。失敗探索は保持し、確認試行として数えない。

予測環境はMuJoCoネイティブ状態・制御器・観測・グリッパー・乱数状態を保存・復元する。保存3場面36分岐で復元後の継続結果一致を確認した。GPU監視は同一物理GPU actorに1つのnvidia-smi常駐プロセスを使い、UUID不一致・3秒を超える古い測定・プロセス異常は欠測として失敗扱いを維持する。

### v0.20.13の監査補正

実モデル探索は固定済みv0.20.12で実施する。v0.20.13では回復指標の分母からウォームアップ中に送信したS1要求を除外し、既存の停止率と同じ境界条件へ揃えた。動作生成・予測・実行処理は変更していない。元リリースの再監査を残した上で補正版でも再計算し、差があれば報告する。
